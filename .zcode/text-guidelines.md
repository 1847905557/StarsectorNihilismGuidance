# Text Guidelines

本文件规定项目文本的编码、字符与 Markdown 呈现。教程页面组织见 `.zcode/writing-guidelines.md`，源码与资源写法见 `.zcode/technical-guidelines.md`。

## 文本基础

- 文本必须使用 UTF-8 无 BOM、LF 和末尾单个换行，行尾无多余空白。
- 中文与英文单词、数字或行内代码之间留一个 ASCII 空格；标识符、URL、路径、版本和代码保持原样。
- 散文括号使用 ASCII `()`，引号使用 ASCII `"`，嵌套时用 `'`，外侧紧邻中文时留一个空格。
- 中文散文使用全角逗号、句号、顿号、冒号、分号、问号和感叹号，省略号写三个 ASCII 句点。
- 破折号使用两侧留空格的 `——`，少用；流程用箭头，名称说明用冒号。
- 引出代码、列表或表格的完整句以冒号结尾。

## 标题与强调

- 文档以唯一 H1 开始，只使用 H1、H2、H3。
- 教程 H1 写宽泛主题或动作对象，示例名称、ID 和参数写在正文。
- 标题写主题，不加 "第一步"、"1." 之类序号。
- 加粗用于关键动作、关键条件和必须记住的结论，一段内不宜超过两处。
- 标签写成 `**标签**：内容`，短语强调的外部标点放在标记外。
- Markdown 排版以项目 Prettier 配置为准。

## 代码与容器

- 代码围栏使用反引号并标注语言；需要提示读者看某几行时可以使用行高亮，即在语言标记后写 `{2}` 这类行号。
- 容器写成 `::: 类型 标题` 与 `:::`，标题写明主题，开始与结束标记和内部正文之间各保留空行。`warning` (黄) 与 `caution` (红) 的严重度差异可作为克制的隐喻，在后果过于隐晦时直接点明严重度，但不滥用。可用类型与职责：
    - `info`：背景与原因。
    - `tip`：操作技巧、命名建议等可选做法。
    - `warning`：常见易错项。
    - `caution`：真正的硬性条件，不遵守就会出错或损坏数据，如贴图尺寸必须为 2 的倍数。
    - `details`：可折叠的长代码、完整成品或作者旁论。
- 核心机制与连续操作写在正文，容器只放可以单独读的补充。
- 较长或多文件的完整成品可以放进 `::: details 完整成品：<类名>`；单文件短代码直接给出。

## 表格

- 表格用于确实适合查表的内容：字段含义、枚举取值、选项对照。
- 表格至少两列、两个数据行，各行列数一致；单元格写一个值或一个短判断，因果和连续操作写成段落或列表。
- 表格可以紧跟引出它的段落或代码，不要求专属标题。

## 引用与资产

- 教程章节编号写成 `[C1-S1]`，编号为无前导零的正整数，链接由插件生成。
- 章页以 `## 本章各节` 和独占一行的 `<!-- AUTO:SECTION-LIST -->` 结束。
- 章页技术基线写成以 `本章技术基线：Starsector` 开头的独立段落，紧接 H1，游戏版本使用反引号，如 ``本章技术基线：Starsector `0.98.5a-RC3` 与 Java 17。``；依赖库写在分号后，如 `；前置依赖：LazyLib 3.0`。
- 节页分割线 `---` 前保留空行，其后两个时间段落写成 `_本节预期阅读时间：\~10 分钟。_` 与 `_本节预期操作时间：\~5 分钟。_`，纯概念页按实际投入填写操作时间。
- `## 常见问题` 每条采用 `- **症状**：原因` 主行，下设缩进 4 空格的 `- **解决方案**：检查位置与修正动作` 子行，条目之间空一行。
- `## 建议参考项` 每项采用 ``- `对象`：说明``；API 参考写完整包名与类名，`starsector-core` 内的文件写相对该目录的路径，其他位置写从 `Starsector/` 开始的路径，不在每一项里重复声明路径约定。
- 相对链接和图片指向存在的文件。
- 图片属于当前页面目录，目标写成 `./文件名`，alt 写观察对象，title 与文件名逐字一致：`![舰船编辑器选择游戏目录](./select_game.png "select_game.png")`。
- 图片前交代要看什么，图片后按需说明不易看出的地方。
