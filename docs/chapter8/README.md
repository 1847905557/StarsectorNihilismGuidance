# 战斗运行时

本章技术基线：Starsector `0.98.5a-RC3` 与 Java 17。

---

截至第七章为止，大多数代码都在游戏启动或装配界面里运行：入口在启动时触发，设置读完就位，舰船属性也在离开车库前预先算完。战斗完全是另一套独立的运行现场，每场开战时创建整套舰船、武器、弹体与特效对象，战局一结束全部丢弃销毁，下一场从头再来。

## 别默认战斗插件只在常规开战时才运行

写全局战斗插件时，最容易忽略的一点是：**主菜单标题画面里同样在实时运行着一场面向玩家展示的完整战斗**。凡是在全局配置里登记的战斗插件，在游戏停留在主菜单、玩家尚未开新档或读档时，就已经被实例化并按每帧推进了。

如果默认插件只会在自己进模拟战或生涯遇敌时才执行，没有提前核对场景就直接读写生涯对象或做重度战场介入，玩家甚至还没进入星图就已经在标题画面里触发报错。**稳妥的做法是在每帧推进入口最前面就检查当前游戏是否确实处于有效战斗态并排除暂停或标题画面**，遍历在场舰船时再顺手同时滤掉处于残骸或离线状态的船体。

## 宿主存续范围决定字段失效时机，如何安放临时状态

战斗层真正考验基本功的，是分清对象挂在哪一层宿主身上：**挂在全场引擎、单艘舰船、单门武器、共用弹体还是独立渲染承载实体上，各自决定了它能保存哪些状态以及什么时候销毁。** 把单发弹体或单艘舰船的私有状态放进共用单例字段里，第一艘船或许刚好正常，第二艘同类船或第二门炮同时开火时就会立刻互相串台。如果共用的武器特效或弹体命中效果确实需要各自维护独立计时或目标标记，**不要往共用效果类里加成员字段，而应当把状态索引进当前战斗引擎自带的临时公共数据表，或者直接存进依附单门武器的每帧脚本实例中**。

此外，战斗回调的时机与挂载方向同样不可逆：伤害修饰接口必须按攻击方还是受击方挂对宿主，挂反了不会报错只会静默失效；命中回调拿到的是已经结算完的终局数值，想要改写这一发本身的伤害，只能在开火瞬间提前动手；而自行注册的渲染对象如果不亲手实现过期判定，就会一直滞留在战场上。
