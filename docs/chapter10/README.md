# 生涯世界与基础服务

本章技术基线：Starsector `0.98.5a-RC3` 与 Java 17。

---

前两章在战斗运行时里折腾的一切，存续周期统统以单场交火为界：战斗结束，引擎销毁，一切临时数值与挂上去的战斗插件随之清零。迈入生涯层之后，面对的是另一份会被完整写进硬盘、跟随玩家跨过几十个小时游戏进程的持久化星区世界。

## 严禁往存档容器里塞大对象与跨生命周期引用

因为生涯状态会跨读档长期存续，动手前最要紧的是想清每一份数据究竟该不该进档、以及能放多重的对象。不管是全局存档字典、挂在星区与实体上的键值内存，还是会随着存档一并序列化的持久脚本，底层最终都会在玩家按保存时递归写进存档 XML。

**严禁往任何存档容器里塞入庞大缓存、临时界面窗口、图形贴图或战场引擎与舰船对象。** 这类跨生命周期引用或大对象一旦被顺带序列化进去，轻则把玩家存档体积撑大到写盘卡顿，重则直接触发序列化异常，让玩家连存档都保存失败。如果某项复杂状态确实需要跨读档保留，**应当把对象拆成轻量的实体标识、枚举、数值或时间戳再存进持久容器，等到读档后凭这些线索现场查表重建活体对象**。

同时，对于开发期还可能改包名或重构掉的脚本，无须依靠字段进档记忆进度的逻辑，优先做成每次读档重新挂载的瞬态脚本。**假如早期已经发布出去某个会进档序列化的持久脚本类，日后想要废弃或替换它时，切勿直接从工程里删除旧类**：正确的兼容退路是保留一个空壳占位类并在读档首帧立刻退出销毁，以免玩家几十个小时的老存档直接崩溃打不开。

## 共享活体对象与失效的官方注释

另一个绕不开的底线在于：星区里的绝大多数核心对象都是全星域共享的活体实例。同一份势力对象同时被原版和所有 MOD 读取，同一个星系平面里混居着各方添加的实体、市场与地形；修改状态之前必须清楚知道自己改的是不是独立副本，若只需影响某座具体对象就修改实例级属性，不要顺手去动共享全局原型或势力总表。

此外，深入生涯底层服务后切忌盲信表面文档：星图位置归属于互相独立的二维空间，时间刻度也并非直接相减就能当成天数，**甚至原版部分接口的官方注释本身就直接写反了引擎真实行为**；当文档、注释和实机渲染发生冲突时，实机运行出来的真实效果才是唯一标准。
