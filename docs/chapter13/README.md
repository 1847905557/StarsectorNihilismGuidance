# 人物与技能

本章技术基线：Starsector `0.98.5a-RC7` 与 Java 17。

---

Starsector 里的具名人物并不天生属于某座空间站或某艘战舰。创建一个人物实例，在数据上仅仅相当于写好了姓名、肖像、阵营与特长卡片；要想让这个角色真正进入游戏世界、被玩家点开对话或对殖民地与舰队产生实际修正，还得把他在好几张彼此独立的名录与岗位表之间逐一安插到位。

## 彼此脱节的登记与露面体系

原版把人物的档案建立、重要人物名录索引、具体势力站点挂载以及通信目录露面拆成了几块互不自动同步的结构。没有先按编号放进全局重要人物名录就去取状态会直接报空；只把人物塞进市场列表而漏掉通信目录，玩家停靠站门口时就根本见不到对话入口；而把一位管理员任命给殖民地，系统也不会自动重新结算产业状态，必须手动再触发一次重新应用才会看到产出变化。

相应地，人物暴露给玩家的入口也应按实际职责区别对待：纯幕后支撑或行政类人物只需要做完名录登记与岗位指派，不必统统塞进空间站通信列表占位置；而真正承载任务交互与势力身份的核心角色，则应尽早通过名录里的独占标记锁定归属，免得其他随机任务脚本在半路把同一个人物抓去顶差。

## 按岗位边界对齐的三线技能口径与拆分做法

角色身上的技能虽然在界面上画在同一面板里，**在底层却分别沿殖民地管理、整支舰队指挥与单舰驾驶三条互不连通的接口体系各自传导**。定义文件里标注的作用域分类与后端实际挂载的效果接口必须严丝合缝地配对；但凡出现界线错配，往往界面说明照常显示，实机数值却纹丝不动。

如果一位角色的设计确实同时兼顾政务治理与带队战斗，**正确的做法是按不同岗位职责拆分成相互独立、作用域清晰的子技能或分组效果各自配对，而不要硬拼进一个试图横跨互不兼容体系的单一效果类里**，结果白白留下一半永远不会被触发的无效代码。
