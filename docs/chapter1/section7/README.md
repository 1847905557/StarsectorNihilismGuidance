# 补充描述文本

到目前为止，本章做出的每艘船、每门武器打开详情都只有一行 `No description... yet`。本节把描述补上。描述文本不影响任何数值，但玩家对一艘船的印象很大程度上来自这几行字。缺少描述的 MOD，数值再精细，看起来也像未完成的作品。

---

_本节预期阅读时间：\~8 分钟。_

_本节预期操作时间：\~10 分钟。_

## 创建描述文件

在 MOD 内创建 `data/strings/descriptions.csv`。列名行与原版 `starsector-core/data/strings/descriptions.csv` 完全相同：

```csv
id,type,text1,text2,text3,text4,text5,notes
```

`id` 与 `type` 一起确定一条描述：同一个 ID 可以同时拥有 `SHIP` 描述和 `SHIP_SYSTEM` 描述，互不干扰。本章用到的类型只有两种：

| 对象       | `id`                            | `type`   |
| ---------- | ------------------------------- | -------- |
| 舰船、战机 | 船体 ID，即 `.ship` 的 `hullId` | `SHIP`   |
| 武器       | `weapon_data.csv` 的 `id`       | `WEAPON` |

战机联队没有自己的描述，界面显示的是战机船体的描述。炉渣的描述行因此写 `GearIn_slag`，而不是联队 ID `GearIn_slag_wing`。

`text1` 是详情页中的正文。其余文本列由特定类型使用，例如战术系统的简短说明，用到时在 [C2-S3] 与 [C3-S4] 讲解；本章只填 `text1`。

`type` 必须是游戏认识的类型名，大小写也要一致，写错时整份文件加载失败。原版的全部取值可以在原版文件的 `type` 列中看到。

## 编写描述

写入本章全部对象的描述：

```csv
id,type,text1,text2,text3,text4,text5,notes
GearIn_durin,WEAPON,拥有可怕射速的自动炮，成箱地发射高爆弹药。,,,,,
GearIn_uri,WEAPON,集束射线，将能量汇聚于一点，能略微地灼伤装甲。,,,,,
GearIn_dwalin,WEAPON,发射大量半制导高爆火箭弹，对于失去护盾的目标造成持续打击。,,,,,
GearIn_slag,SHIP,略大于寻常战机的突击机，擅长在相对更远的距离倾泻动能火力。,,,,,
GearIn_forging,SHIP,借由哨兵-级蓝图修改而成，粗暴地为它加装了一副相位线圈。它广受置生死于度外的舰长们的喜爱，却往往深受船员的忌惮。,,,,,
GearIn_furnaceman,SHIP,在赶牛人-级航母的框架上加装更多炮塔，这种航母拥有更稳健的防御能力。,,,,,
GearIn_artizan,SHIP,对锤头-级驱逐舰进行部件替换的尝试，它搭载了比想象中更高端的武器配备，和一副实验性抵抗力场。,,,,,
```

描述是写给玩家看的设定文本，与数据从哪艘原版船复制无关。工匠的 "实验性抵抗力场" 要到 [C2-S3] 才会做出来，提前写进描述并无不可。

## 转义文本

上面的描述只用了中文标点，所以不需要任何转义。一旦正文里出现半角逗号、双引号或换行，就必须按 CSV 规则处理：

| 正文包含 | 写法                                     | 示例                          |
| -------- | ---------------------------------------- | ----------------------------- |
| 半角逗号 | 用一对半角双引号包住整个字段             | `"Durin, the autocannon"`     |
| 双引号   | 包住整个字段，并把正文中的 `"` 写成 `""` | `"偶尔也被称为 ""热熔枪""。"` |
| 换行     | 包住整个字段，换行留在引号内             | 见下例                        |

```csv
GearIn_artizan,SHIP,"对锤头-级驱逐舰进行部件替换的尝试。

它搭载了比想象中更高端的武器配备，和一副实验性抵抗力场。",,,,,
```

引号内的换行属于正文，在详情页中显示为分段；引号外的换行才结束这一行。原版的长描述大多这样分段。

::: caution 引号必须是半角直引号

包住字段的引号只能是 `"`。中文输入法打出的 `“”` 是普通文字，不会保护其中的逗号，这一行的列随之错位。

:::

行首为 `#` 的行是注释，整行被跳过。分组标题、暂时停用的描述都可以这样处理。

1. 保存文件并重启游戏。
2. 在控制台执行 `Addship GearIn_artizan` 与 `Addweapon GearIn_durin`。
3. 在货舱中把鼠标悬停在都林上，详细说明位于数据面板上方：

![武器描述在界面中的显示位置](./desc_weapon.png 'desc_weapon.png')

4. 在舰队界面打开工匠的详情，正文位于船体标题下方：

## 常见问题

- **详情显示 `No description... yet`**：描述行的 `id` 或 `type` 与对象不对应，例如为炉渣填了联队 ID。
    - **解决方案**：舰船和战机填船体 ID 与 `SHIP`，武器填武器 ID 与 `WEAPON`。

- **加载时报 `Mismatched quotes in the string; last quote: [...]`**：某个字段的引号没有成对，或正文中的双引号没有写成 `""`。
    - **解决方案**：从报错位置开始逐个检查引号，保存后重启。

- **加载时报 `Key [type] has invalid value [...]`**：`type` 拼写或大小写错误，或因列错位而读到了别的内容。
    - **解决方案**：改为正确的类型名，并确认该行之前的字段都已正确转义。

- **加载时报 `Duplicate key [...]`**：同一个 `id` 与 `type` 的组合登记了两次。
    - **解决方案**：删去重复的一行。

- **正文被截断，后半段消失**：正文中的半角逗号没有被引号保护，后半段进入了下一列。
    - **解决方案**：用半角双引号包住整个字段。
