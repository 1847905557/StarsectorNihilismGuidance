# Technical Guidelines

本文件规定教程与 fixture 的技术事实、示例身份、Java 写法和完整成品契约。教学组织见 `.zcode/writing-guidelines.md`，文字呈现见 `.zcode/text-guidelines.md`。

## 版本与事实

- 教程使用 Starsector `0.98.5a-RC3` 与 Java 17，章页声明游戏版本、适用 Java 版本和所属依赖库与版本。
- 技术行为必须依据公开 API、公开实现或游戏内直接观察确认，严禁采用或暗示反混淆产物。
- 技术事实直接说明实际对象、行为、条件、近似性质和适用范围。
- API、字段、ID、路径、日志、命令、数据和数值保持准确，文字改写保持技术含义。
- 散文版本数字用于版本行为差异或 API 新增移除，代码、数据和日志中的版本字符串保持原样。
- 验证中的运行期动态值可以紧贴使用 `以实际日志为准`，技术结论对应实际执行范围。
- 源码引用使用稳定类名、方法、字段或路径，数值服务判断、操作、布局、参数取舍或完整性核对。

## 示例身份

- 示例 MOD ID 使用 `gear_in`，数据、资源和 strings 键使用 `GearIn_<subject>`。
- Java 包使用 `data.scripts.gearin.<domain>`，按 `combat`、`campaign`、`rules` 等实际职责组织，保持共享入口归属。
- Java 类名使用表达角色的 `GearIn<Role>`，教程单元编号 `Cxx-Syy` 用于页面和核验工程身份，严禁进入运行时名称。
- 新 ID 由一个页面定义，其余页面按相同含义复用并引用定义页，已有 ID、资源和对象保持实际归属。

## Java 与教学代码

- 每个 Java 类承担一个角色，多个接口共同服务该角色，跨角色实现分别组织并说明绑定位置。
- HubMission、HullMod、技能效果、战斗渲染和 ShipSystem 按实际对象职责组织。
- 工具库页面围绕所需功能提供短用法与组装入口，数据页展示实际数据和制作步骤。
- 示例先说明问题，再展示当前动作需要的片段，交代写入位置、调用关系、生效条件与观察方法。
- Java 教学逐步解释新增对象、参数和行为，再给完整成品，局部片段数量由任务确定。
- 局部片段标明用途，完整类包含实际包、import、入口和依赖。
- 设置型片段在注册、安装、构建或接入后的首个运行点确认结果，完整代码后的解释围绕入口、数据流、关键判断与结果。
- 故障演示采用真实可达条件，说明症状、原因与修正，明确标识局部故障和局部修正片段。
- 输入判断对应实际生命周期或外部输入条件，封装、依赖和异常处理服务明确需求。

## 完整成品与 fixture

- 页面完整 Java 类必须与所属 fixture 逐字一致，源码路径由包与顶层类名确定。
- 每个 fixture Java 文件必须在所属页面出现完整代码，每个完整 Java 类具有 fixture 和编译清单项。
- 完整 shader 必须以 `#version` 开头，与对应 `.vert` 或 `.frag` 资源逐字一致，并登记到 `shaderUnitIds`。
- 页面、fixture 目录、源码、资源和 Gradle 清单双向对应，完整代码与注册入口、资源路径和依赖一致。
- 局部 Java、GLSL 和解释性数据承担教学讲解，完整源码匹配集合由实际成品组成。
- 读者使用的构建与游戏验证归教程正文，fixture 路径、编辑侧任务和作者执行结果归工具说明与任务记录。
- 完整类容器与成品章节按 `.zcode/text-guidelines.md` 和 `.zcode/writing-guidelines.md` 组织。
- 原版、依赖库和教程自身事实采用相同准确性要求，核验结果对应实际执行内容。

## Java 与资源格式

- Java 使用 4 空格缩进，续行相对语句起点缩进 8 空格，方法、条件和空实现的大括号展开。
- import 组内按字母排序并保持紧凑，组间沿用所属组织。
- 注释与 Javadoc 简短自含，类注释长度由角色说明需要确定。
- 分节横幅采用 `// --- 标题 ---`，注释引号使用 ASCII 双引号。
- JSON、CSV、`.skill`、`.variant`、`.txt` 和 shader 按自身语法与项目样本排版，宽松 JSON 的注释、尾逗号和 Tab 按游戏解析语义处理。
- 源码与资源的编码、换行和末尾格式见 `.zcode/text-guidelines.md`。
