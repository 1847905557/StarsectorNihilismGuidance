# 文件读取与写入

本章技术基线：Starsector `0.98.5a-RC7` 与 Java 17。

---

到这一章为止，前面已经穿过静态资产、工程化、战斗与生涯大部分机制。随之而来的工程整理需求，通常集中在三类文件上：随包分发的只读配置、脱离单份存档留存的客户端记录，以及面向多语言或集中改稿的界面文案。

## 非必要绝不写进文件

学会读写外部文件之后，最先应当坚持的一条原则反而是克制：**非必要绝不写进文件**。把算法内部魔数、公式系数乃至根本不打算给他人改动的核心逻辑阈值统统塞进配置文件。这样做的唯一结果，是平白在源码与运行期之间多加一层文本解析与格式报错风险，而且完全是自找麻烦。

**真正值得拆出代码的东西只有三类**：专门开放给平衡调整者或玩家微调的设置、必须跨越单份存档独立保存在本地的客户端统计，以及需要统一润色或多语言替换的界面提示文本。**至于那些仅仅是在工程内几个类之间共用、却压根没打算暴露给外人修改的核心逻辑常数，直接写成源码公开静态常量由编译器守住即可**，零解析开销也完全不受外部误改牵连。

## 跨区隔离与缺损容错的不同尺度

数据一旦离开编译器的保护范围，立刻就要面对文件覆盖冲突与外部篡改风险，而且不同位置的文件应对尺度完全不同：随 MOD 打包的只读配置区分全局覆盖还是仅锁定本包目录，自家专属参数务必带上完整模块标识，缺键时直接抛出启动异常反而比悄悄套用默认值更容易在第一时间暴露错改；而写入全局共享用户空间的客户端记录不仅要死守独特文件名前缀防止撞车，**还必须在读取入口主动捕获格式损坏并安全回退初值**，避免因为一份统计文件里少了个逗号就把玩家正常读取游戏彻底卡死。
