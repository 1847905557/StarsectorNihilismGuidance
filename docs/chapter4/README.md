# 战役与无代码对象

本章技术基线：Starsector `0.98.5a-RC7` 与 Java 17。

---

前面已经摸过了静态表和短脚本，但游戏里还有一整批彼此相对独立的内容制作项，几乎不需要写什么正经逻辑代码：复制一份原版配置改掉对应参数，就能往游戏里添上新的测试手段、外观风格、复合船体乃至星图天体。

## 测试场地与 "普通但极限" 的装配标准

**原版已有的无代码配置能力足以支持相当多样的设计变化**，动笔写代码之前先看一眼原版配置能不能解决，常常能省掉不少额外工时。在这之前，最值得尽早做出来的是一张专供作者反复试船与导出装配的测试战役，配上一座耐打、火力均衡且不会乱跑的固定大型靶标与基础视野环境作为恒定参照，往后每次改武器数值或试船都能在同一把尺子下对比手感，利用率远高于正式生涯。

至于放进模拟战与势力常规编制的舰船装配，应当守住一个清晰的基准：**采用游戏内常规渠道就能凑齐的满装配点、无 S 插、无稀有特殊武器的 "普通但极限" 规范**。如果一艘船本身兼顾多种玩法，完全可以按近身爆发、远程压制或护航支援各自做一套定位鲜明且拉满常规上限的配置；真正不合理的是靠满 S 插与特殊装备去虚撑常规面板，而不是把普通装配做到尽头。

## 认清原版无代码扩展的别扭处与现实妥协

虽然不用啃复杂 Java 代码，但原版在部分无代码特性上的拼接其实相当别扭：模块船少加一个标志位就会在进战场时把子模块凭空弄丢；而自定义舰船外观风格一旦新开编号却没有跟着补齐全套配套引擎音效，游戏就会直接回退套用欧米伽船体的默认引擎音，实战观感立刻出戏。

如果手头暂时没有精力为一套全新外观补齐整套专属音效，**最稳妥的替代方案反而是直接沿用并与相近原版科技风格保持一致，只在武器与少数核心外观元素上做局部区分**，既不破坏整体音画统一感，也省掉无谓的资产返工。
