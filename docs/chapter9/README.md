# 战斗内容扩展

本章技术基线：Starsector `0.98.5a-RC7` 与 Java 17。

---

第二章通过复制修改原版短脚本，已经能让船体插件改动属性、让战术系统开启加速、让武器命中后追加一次爆炸。但一旦进入真正完整的战斗机制制作，只做到让脚本不报错往往会露出许多生硬破绽。

## 简洁自洽也是好设计，掉价的是半成品偷工减料

先要破除一个常见误解：效果做得简单并不代表简陋。**只要定位清晰、逻辑完整自洽，极其简洁的战斗效果照样是经得起跟原版摆在一起比较的好设计**；真正让一个 MOD 显得粗糙掉价的，是在实现过程中绕开了那些本该补全的边角细节。

如果精力或题材本就适合走轻量路线，**更稳妥的做法是主动回避拿多个半吊子复合效果去凑篇幅，刻意把功能收窄成一个焦点清楚的单一机制，把围绕这个单点机制的互斥拦截、随充能进度平滑过渡、基础 AI 释放时机与缺帧判空防呆一次做实**。反过来，互斥只拦截一半让玩家白拿双倍加成、增益开关瞬间生硬跳变、系统由不合拍的内置 AI 胡乱挥霍、或者多帧贴图遇上静态武器直接空指针报错，这些偷工减料的缺口，才是把设计拉进半成品行列的原因。

## 对原版单例、全星区回调与反直觉接口的应对办法

更棘手的是，这一层原版接口的坑比前两章硬得多。**船体插件类在整个游戏会话里是全局单例，绝不能在实例字段里保存任何单艘舰船的计时器或状态**；如果插件效果确实需要在战斗中逐艘追踪状态，同样应当把状态寄存在战斗运行时的临时数据映射或独立伴生脚本里，只在装配预览外生效。开启作用于整支舰队的同步开关时，生涯中全星区的每一支 AI 舰队都会频繁调进回调，务必先过滤已封存船体、加上限并按需启用接口，不要把无谓的重计算强行挂到全星区头上。

此外，切勿仅靠直觉或接口命名的字面意思猜实现方式：原版不仅存在命名和继承结构完全脱节、甚至压根不存在的假接口名，帧图编号规矩也极为死板，动手前先核对一遍原版真实同类实现往往能省下大半冤枉工夫。
