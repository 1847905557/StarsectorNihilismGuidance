# Rules 系统、命令与内存

本章技术基线：Starsector `0.98a-RC8`，Java 17。

生涯中的许多交互由 Rules 组织：游戏在特定场景触发查询，规则根据当前状态决定显示什么文字、提供哪些选项，以及接下来执行什么动作。此前的酒吧示例已经用到了这套机制，本章继续展开它的匹配、执行与回流关系，让规则能够承接具体的交互需求。

**规则的含义由数据与调用场景共同决定。** 同一条命令放在条件列或脚本列，返回值的用途就有所不同；同样的变量写法，换到另一种对话中也可能读取不同对象。编写分支时，除了文字与条件，还要明确触发入口提供哪些状态、获选结果承担哪些工作，以及选项如何接回原有菜单。

Rules 与 Java 可以共同完成一段交互：规则组织条件、文本与选项，Java 命令处理所需操作，Memory 让双方读取和保存对象状态。掌握这些关系以后，就能在已有生涯场景中加入自己的内容，并让后续交互依据实际发生的事情作出变化。
