# 基础及舰船相关

本章技术基线：Starsector `0.98.5a-RC7`。

---

一个 MOD 能不能在玩家眼里立足，第一轮体验往往就已经定了一半胜负：舰船、战机与武器，是玩家打开游戏后每一场战斗都要亲手操纵与直面的实体。无论后续叠加了多少生涯剧本、势力事件或华丽的渲染管线，只要战场上直接交手与操纵的实体底子发虚，后面写再多代码都只是在浮沙上加盖楼层。

## 贴图标准与作者能力天花板之间的取舍

打开本章示例时，您很快会注意到里面拼出来的舰船与武器贴图十分粗糙。这一点必须在动手之前先说清：**不要把教程里的粗糙拼图当成正常发布标准**，之所以用不到一分钟拼出这些简陋贴图，目的只是替不擅长画图的初学者压低门槛，证明**哪怕拿最简陋的拼图也照样能从头跑完一个完整可玩的入门 MOD**。

若按真实发布口径来看，只要条件允许，**用心制作并公开发布的作品应当争取让所有贴图在登场那一刻就达到最佳状态**。玩家打开列表看见舰船的第一眼，几乎就决定了愿不愿意继续试驾与订阅；一旦在发布初期留下美术粗劣的第一印象，往后往往会遭遇滚雪球式的信任与口碑困境，哪怕后期再花数倍功夫翻新，也很难把原本劝退的玩家再请回来。

当然，绝大多数个人作者并没有专业美术功底或外包预算。受限于自身美术上限时，务实的出路**不是硬着头皮手绘一堆形状歪斜、光影格格不入的拙劣原画硬塞进舰船表，更不是拿半成品草图直接发出来指望以后再改**：您可以选择老实**利用原版素材进行整齐严谨的裁剪拼接与调色复用** (保持与原版一致的像素密度、边缘抗锯齿和受光方向)，或者控制战线规模、把精力集中在少数几艘打磨到位的核心舰船上，甚至寻求合作美术或使用合规授权的社区开源素材包。在自身能力范围内守住审美下限与风格统一，远比勉强原创却画得难看更体面。

## 存在的理由，先于面板数值

**编者对本章只有一个硬性要求：为您做的每一样东西找到存在的理由。**

原版游戏的船体、战机与武器数量已经足够庞大，绝大多数常见的定位与火力区间早已被填满。只靠把射程多加两百、护盾效率抬高一成，或者往船体上塞进一堆拆不掉的内置加成来证明 "强力"，这类作品任何人花上半小时都能批量做出来，却不会有任何一件留在玩家记忆里。

在还不会写自定义代码的前期，差异化同样不靠膨胀面板来凑。**完全可以通过特殊的武器槽位分布、刻意的射界死角、反直觉的幅能与极速搭配，或者为某几类现成武器定制专属承载平台，做出原版船体里找不到替代品的驾驶手感与战术取舍**；哪怕代码一行未写，这样明确有来有回的设计依然成立。

::: tip 本阶段的能力边界

本章全部操作都在数据表与静态资产内部完成，先不主动引入自定义代码逻辑；最小尺度的脚本改动会在第二章切入，真正的独立 Java 工程化则留在第六章。另外，舰船编辑器与数据配置向来算不上严丝合缝，越早理顺这些静态约束，后面写代码时就越少回头返工。

:::
