# 无需入门的代码修改

本章技术基线：Starsector `0.98.5a-RC7` 与 Java 17。

---

上一章只碰静态数据文件，能调整的无非是写死的数字上限。只要您的设计需要按条件才触发的强化、命中船体时追加的效果，或者随船体级别自动缩放的加成，单靠改表就已经行不通了。

## 借用外壳，但必须弄清自己动过的那几行

跨出静态表这一步免不了要接触 Java，但本章既不预设您懂语法细节，也不打算从头充当编程语言入门书。原版绝大多数船插、战术系统与武器特效本质上都只是几十行的短脚本，结构高度相似。面对一份七八十行的原版代码，**您不必立刻把里面的每句语法与渲染辅助细节全啃穿：先把入口方法、触发条件以及哪几行改写了数值或伤害定位出来，保持其余外围调用结构原样不动**，只盯准自己亲手改动的那几行理解清楚原理，就足够稳妥地改出自定义效果并有底气排查报错。至于完整的 Java 语法与工程化组织，留到第六章再全面接管即可。

## 文字交代、数值账目与单向约束的替代解法

写这类短脚本时，有三处最容易只顾着写效果却忘了收尾：

- **文字说明必须完整如实反映全部情况**：除开画面呈现，文字是玩家理解机制的直接依据；如果条文实在过长需要精简，也**应当保留全部核心前提、触发阈值与负面代价，仅删掉重复修饰的废话**，而在篇幅本就不长的情况下更应当一次把所有分支情况写明白。
- **特效比重必须自己算清**：追加爆炸或系统增益不能只顾叠加数字，必须先对照主武器本体的平均每秒输出与开启节奏算清增幅比例，避免副产物反过来掩盖主武器定位。
- **原版不会对称拦截时的退路**：涉及互斥或跨插槽联动的限制往往只能单边检查，因为原版船插根本不认识您新增的条目。在无法改动原版代码的前提下，除了在己方代码一侧做好拦截并在说明里标清兼容边界外，更干净的做法是**主动避开与原版高频通用插槽直接竞争同一机制定位**，从设计上减少互相叠加成畸形数值的可能。
