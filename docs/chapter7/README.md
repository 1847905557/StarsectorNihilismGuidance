# 全局服务

本章技术基线：Starsector `0.98.5a-RC3` 与 Java 17。

---

前六章做出的一切成果，玩家都能在屏幕、装配面板或战场交火中直接看到或听到。到了这一章，表面上做完之后游戏看起来跟没装这个 MOD 几乎没有区别，但往后所有系统能不能稳妥起飞、出了报错能不能迅速定位，全压在这几层看不见的公共基建上。

## 进程期与存档期，外加绝不跨域存引用

接手入口类、全局配置读取与动态音效接口时，最致命的隐患都集中在生命周期边界上：

- **区分游戏进程与单一存档的存续范围**：入口类实例在游戏启动时创建，并一直存续至整个进程退出，而玩家的存档是一份一份切换的。把本该只在开新档运行一次的逻辑塞进每次读档回调，或者反过来把单份存档的运行状态留在入口类字段里，都会在玩家退回主菜单切档时制造出跨档污染；如果某个逻辑既需要在进程内复用又跟单一存档绑定，**正确做法是把它放进存档自己的持久化容器里，而不是挂在入口类成员变量上**。而在游戏刚加载全局资源、生涯星区尚未初始化前就去读取星区对象只会抛出空指针，必须先做状态隔离或把星区读取延后到进档回调再执行。
- **严禁跨域保存引用，坚决防止内存泄漏**：绝不把属于单场战斗的上下文对象、战斗引擎实例或单局舰船直接存进全局静态字段、入口类成员或生涯对象里。一旦战场引擎上下文通过这种隐蔽引用泄露到生涯层或进程级静态域中，单场战斗结束后整套战场资源就再也无法释放，轻则内存一路泄漏，重则在后续读档或再次切入战斗时拖垮整局游戏。**真正需要把战局战果传回生涯时，应当在结算或退出战斗的瞬间只提取纯原始数字、布尔标记或字符串标识写进生涯容器**，彻底切断与任何战斗现场对象的直接联系。

## 排错先追最早期栈帧，不凭直觉猜测

功能越多，出异常时越不能靠猜来改代码。排查运行日志时始终直接翻到末尾，从上往下找到第一个属于自己包名的调用帧，顺着最早出现的根因异常往回追；同时把全局配置的必填校验口径与动态声道分工在这一章一并理顺，后续各章才会不再频繁回头返工。
