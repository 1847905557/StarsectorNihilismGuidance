# Text Guidelines

本文件规定项目文本的编码、字符与 Markdown 呈现。教程页面组织见 `.zcode/writing-guidelines.md`，源码与资源自身写法见所属语言规范和 `.zcode/technical-guidelines.md`。

## 文本基础

- 文本必须使用 UTF-8 无 BOM、LF 和末尾单个换行，行尾保持整洁。
- 中文与英文单词、数字或行内代码之间留一个 ASCII 空格，标识符、URL、路径、版本、百分数和代码语法保持实际字符。
- 散文括号使用 ASCII `()`，引号使用 ASCII `'` 或 `"`，外侧紧邻中文时留一个空格，内侧按内容自然连接。
- 界面、日志和引用原文使用 ASCII 双引号，嵌套引用使用单引号，普通引述按语义选择直接陈述或引用。
- 中文散文使用全角逗号、句号、顿号、冒号、分号、问号和感叹号，省略号使用三个 ASCII 句点。
- 破折号使用两侧留空格的 `——`，承担句中补充、转折或总结；流程使用箭头，名称说明使用冒号。
- 单字符 `—` 用于表格无数据占位，层级使用 Markdown 标题与列表，反斜杠承担实际转义或语法用途。
- 代码、字符串和资源中的技术字符保持实际语义，注释遵守所属语言和散文约定。

## 句末与段落

- 独立句按句法收束，标题、短语、标签、路径、命令、公式和技术枚举保持各自句末形式。
- 引出代码、列表或表格的完整句使用冒号，同组并列独立句统一句末形式。
- 同一主旨用自然段展开，独立操作和并列信息按职责使用列表，源码换行服从语义。
- 连续操作使用有序列表，无序列表与强调标记由 Prettier 统一，嵌套内容属于对应主项。
- 固定验证动作、预期结果和参考项使用紧凑列表，故障条目间距见 `.zcode/writing-guidelines.md`。

## 标题与强调

- 文档必须以唯一 H1 开始，标题使用 H1、H2、H3 并表达实际语义。
- 教程 H1 表达宽泛主题或动作对象，示例品牌、ID、参数与运行细节归正文；第 3 章 H1 使用动作与宽泛对象。
- 章页技术基线紧接 H1，使用以 `本章技术基线：Starsector` 开头的独立普通段落，游戏版本使用反引号。
- 修改章介绍时必须逐字保留既有技术基线整行，Java、依赖和前置知识沿用所属章的行格式。
- 加粗用于快速阅读摘要、核心结论、关键动作、关键条件和作者立场，密度取决于实际语义。
- 短语强调的外部标点放在标记外，整句强调包含句末标点，标签使用 `**标签**：内容`。
- Markdown 标记和排版采用项目 Prettier 配置，文字标点与间距按本规范处理。

## 代码与容器

- 代码围栏使用反引号，长度由内容中的反引号决定，语言标记与内容一致。
- VuePress 容器采用 `::: 类型 标题` 与 `:::`，标题写明信息主题、动作或风险。
- 提示容器简洁自含，集中处理当前操作的具体限制、隐蔽后果、特例或可选用法。
- 核心机制与连续操作在正文展开，作者旁论使用主题明确且有独立阅读价值的 `details`。
- 背景与原因使用 `info`，操作技巧使用 `tip`，常见易错项使用 `warning`，强制风险使用 `caution`。
- 每个完整 Java 角色类必须使用独立 `details` 容器，标题采用 `完整成品：<类名>`。
- 示例容器、代码解释和正文保持说明连续，层级对应实际信息职责。

## 表格

- 教程表格用于字段、枚举、职责、选型或独立规则的速查，每行可独立阅读，各列保持同一语义。
- 每张教程表格由唯一 H2 或 H3 管理，标题包含 `速查表`，其后可以有一段普通引言。
- 表格至少包含两列和两个数据行，保留合法分隔行，各行列数一致。
- 单元格承担一个值、短语或完整判断，完整因果和连续操作使用自然段或有序列表。

## 引用与资产

- 教程章节编号使用 `[C1-S1]`，编号为无前导零的正整数，链接由现有插件生成。
- 章页在 `## 本章各节` 后单独保留 `<!-- AUTO:SECTION-LIST -->` 并以此结束，节列表由插件生成。
- 相对链接和图片指向存在的目标，教程路径符合读者可获取的文件位置。
- 图片必须属于当前页面，目标使用 `./文件名`，alt 表达非空语义，title 逐字符匹配原始文件名。
- 图片说明写观察对象，文件名由 title 保存；图片前交代观察目标，图片后按需说明难辨关系。
- 图片格式可读取，构建哈希图片和 data URI 的恢复交给现有恢复工具。
