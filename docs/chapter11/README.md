# 生涯舰队与舰队成员

本章技术基线：Starsector `0.98.5a-RC3` 与 Java 17。

---

上一章放进星图的行星、遗迹与信标都固定在各自轨道上；整个生涯世界里真正会跨星系航行、会主动接战、被击溃后还能按周期重新生成的动态载体，只有舰队。想让势力在星区里真正运行起来，建好几支能巡逻、接战并自我补充的舰队远比多摆十颗行星管用。

## 外层调度与内层编制的分离，以及稳妥的装配做法

星区把舰队拆成了分工明确的上下两层：外层负责星图上的实际实体、空间坐标与行动队列，内层负责整支舰队的船体列表、军官编制、战损与每条船的具体装配。

两层的接缝处分布着不少极易踩空的细节：生成工厂在势力缺少可用蓝图或点数不足时可能直接返回空结果，不会自动补足空船；往星系放置舰队时如果只登记实体而漏设坐标，舰队就会直接刷进恒星中心坐标的日冕里；手动向单船指派舰长时若忘了同步记入整支舰队的军官编制，人物就会在舰队面板上隐身；甚至连已加入的任务队列都可能在遭遇战结束后提前清空，必须挂着循环脚本持续盯住队列状态。常规批量编队时，**尽量按势力既有的舰船角色预设让工厂抽船成军，只在需要突出少量旗舰或特种配置时才在代码里逐格微调**，既省工时也少出一堆字段错漏。

## 严禁直接修改全局原型与套用玩家维修规则

操作内层船体与后勤状态时，还有两条必须配合替代方案一起落实的技术边界：

- **修改单舰装配必先复制副本再写回**：通过成员接口取到的装配对象，初始状态下往往直接指向全局静态原型；若不先复制出独立副本就动手删改武器或船插，等于把全星区此后新生成的所有同类舰船一并改坏。改完独立副本再重新写回成员接口，才会只作用于眼前这一艘船。
- **NPC 舰队修整走靠港直接状态重置，别套玩家后勤维修**：玩家舰队的渐进维修机制强依赖货舱里的补给存量推进，而 NPC 舰队在底层并没有真实的日常补给消耗账户；错把这套机制挂给 NPC 舰队，只会让它在战损后永远卡在半路修不满船。**合理的替代路线是在巡逻队接战受损并按任务撤回母港之后，直接通过状态重置脚本一次性修复船体并重新派巡**，干净利落且不会卡死状态。
