# 生涯脚本与情报事件

本章技术基线：Starsector `0.98.5a-RC7` 与 Java 17。

---

星区、舰队、市场与人物各自就位之后，接下来的核心问题是怎样让这个世界脱手自行流转：按天数推移切换站点态势、在舰队遭遇战后记住玩家行为、按状态决定是否截断常规停靠，并把正在发生的星区动态干净地投射进玩家的情报面板。

## 轮询、事件与情报的各归其位

原版为此拆出了几条互为补充的扩展路径，动手前先按需求挑对承载方式能省掉大批麻烦。需要自身保存倒计时或阶段翻转的周期管理器适合随档保留；只需监听外部事件并改写内存标记的处理器，则优选做成每次读档时重新挂载的瞬态组件，既减轻存档负担也不怕后续类名重构。同理，表现持续动态的情报也有两条明确选型：**只要统计现成星区巡逻或势力近况，就做成按需现场检索的无状态实时情报，省去额外进档脚本；只有带有明确起止倒计时的限时行动，才配用生命周期管理定时退场**。

在每帧推进的脚本里应当搭配随机节流间隔工具降频执行，没必要每一帧都扫遍整片星区；而在处理战斗结算或市场事件监听时，**筛选条件少写一项就会记混别家的账**：只筛所属势力会把己方商船与补给船算成巡逻队，只按巡逻标记筛选又会把全星区其他势力的巡逻队一并算在自己头上。

## 多 MOD 共存下的插件优先级与弹窗礼仪

当自定义生涯插件参与裁决弹窗接管时，**切勿图省事一律返回最高优先级**。原版常规对话停靠的接管权重极低，绝大多数只需覆盖常规入口的场景返回普通模组级优先级就已足够压过原版通用处理，把最高优先级礼让给真正全局重写的底层大修模组即可。同时每次拦截都应构造全新的对话插件实例，绝不可缓存成员变量跨弹窗复用；开局玩家尚未听说过某个势力时也别打开左下角强提醒弹窗突兀刷存在感。
