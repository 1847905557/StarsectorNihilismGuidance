# 酒吧事件与任务

本章技术基线：Starsector `0.98.5a-RC3`，Java 17。

---

常规文本分支可以靠上一章的规则表硬撑过去，但只要交互涉及现场算账、按条件动态禁选按钮，或者跨星系推进多步状态与退场清理，规则表很快就会力不从心。此时需要把流程切回自定义对话插件与阶段任务状态机，再解决好它们与原版界面之间的接管和归还问题。

## 对话接管、同窗交还与交互线索

使用自定义对话插件拦下原版流程时，界面设计上有两条直接影响玩家体感的细节：**因为条件不足而暂时不能点选的分支应当灰显并写明门槛，如无特别原因切忌直接隐藏**，彻底藏起来会让玩家以为根本不存在这条路。

而在处理完盘查、交涉或特殊遭遇后，只要弹窗本身还没有关掉，就应当在同一个窗口里把控制权顺滑交还原版停靠菜单，不要为了图省事直接关闭界面逼玩家退回星图再重新停靠一次；交接时初始化与切换插件的调用次序一旦写反，新界面添加出的按钮就会留在旧插件里毫无响应。

## 用既定阶段框架托管耦合流程与退场清理

到了酒吧偶发遭遇与长线委托这一层，原版底层实际上又把 Java 状态机和静态调度表、规则表再次拧成了一套耦合结构：Java 类只管划定任务阶段、标注星图目标与收尾清理，而让它在酒吧露面、弹出说明并把进度键写进全局，依然要靠表格规则接力驱动。

对于跨星系跑腿或多步骤委托，**最省心的替代做法是直接基于原版自带的阶段任务基类去声明阶段枚举与自动清理规则，让框架统一托管星图标记、情报更新和任务结束时的退场抹除**，切忌自己在外面用零散的全局监听器和硬编码定时标记去硬模拟整条任务链，只要少擦掉一个目标或冷却键，玩家的星图上就会留下一堆永远清理不掉的死信标。
