# Rules 系统、命令与内存

本章技术基线：Starsector `0.98.5a-RC7` 与 Java 17。

---

前面搭起了市场、人物、事件监听与生涯插件，但只要玩家点开人物通信目录、推开停靠菜单或者对着某座空间站挑选项，游戏大部分时候还是会一头扎进原版的对话规则系统里。

## 认清现实：一份为非程序主笔准备的无代码轮椅

在正式动手写规则之前，先把实质说透，没必要替它找什么美化理由：**原版规则表本质上是主程序给不懂编程的主笔准备的一套无代码轮椅**。它没有正经的树状流程控制，每一轮交互全靠引擎整表扫描条件、挑出权重最高的那一条去拼台词和按钮；这套机制设计得极其古板，运行效率低下，写起来更是几乎没有规范性可言。

之所以到了 Java 工程阶段仍然不得不捏着鼻子去学它、用它，绝不是因为它有多优雅，纯粹因为**原版引擎自己先把大量停靠菜单、通讯频道与人物交互流程从 Java 硬切进了规则表里**。外挂代码如果想绕开这套规则表、强行把所有原有分支重新逆转拦截回 Java 侧接管，代价大到完全得不偿失，权衡之下只能继续借它的通道接入自家交互。

## 止损做法：表格留流转，计算退回 Java，接通原链末尾

既然绕不开这套历史轮椅，唯一清醒的应对方式就是把它的职责死死限制在最低限度：**让规则表只管触发时机、文本展示与选项流转，但凡碰到需要算动态价格、校验货舱余量或批量改写状态的操作，立刻通过注册好的自定义命令类退回 Java 里处理。**

实际编写时还有几条止损惯例能大幅减少返工：同一触发时机下同分规则尽量靠互斥条件彻底隔开，并用中等梯度的权重点数压过原版通用问候的同时让开拉黑拒听等高优先级规则；若只是改写原版站点停靠或通联流程里的中间一截，**脚本末尾务必把控制权转发回原版原有的后续触发时机**，避免顺手把后面的交易或交战菜单一并截断。再配上理清前缀划分与缺省作用域的约定，就能守住表格轻量化而不至于写出一份彻底没人读得懂的巨型长表。
